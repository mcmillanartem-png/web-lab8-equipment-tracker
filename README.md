# Учёт оборудования лаборатории

**Учёт оборудования лаборатории** — веб-приложение для лаборанта или заведующего лабораторией. Оно хранит список всего оборудования (приборы, инструменты, компьютеры) и показывает, **что сейчас свободно, а что выдано и кому**.

Вместо бумажного журнала выдачи всё оформляется в пару кликов: выбрали прибор, указали, кому выдаёте, и приложение само отметит его как «В использовании». Выдать один и тот же прибор двум людям одновременно невозможно.

Приложение удобно и на компьютере, и на телефоне, его можно установить как обычную программу (PWA).

## Для кого и зачем

- **Лаборанту** — вести учёт оборудования и оформлять выдачу и возврат.
- **Заведующему** — в любой момент видеть, какие приборы на руках и у кого.
- **Разработчику** — подключить учёт к другим системам через API.

## Возможности

- **Каталог оборудования:** название, тип, серийный номер, статус. Добавление, просмотр, изменение, удаление.
- **Фильтры** по типу (измерительное, инструмент, компьютер…) и по статусу (свободно / в использовании).
- **Выдача** в модальном окне: кому и с какой даты.
- **Возврат** одной кнопкой, из таблицы или со вкладки выдач.
- **Статус «В использовании»** с именем того, у кого сейчас прибор.
- **Вкладка «Активные выдачи»:** всё, что сейчас на руках.
- **Защита от ошибок:**
  - нельзя выдать уже выданный прибор;
  - нельзя удалить прибор, пока он не возвращён;
  - серийный номер не может повторяться;
  - пустые поля не принимаются.
- **Понятные сообщения** об успехе и ошибках.
- **Адаптивный интерфейс:** таблица и окна удобны на телефоне и на компьютере.
- **Доступность:** работа с клавиатуры, подписи для экранных дикторов.
- **Установка как приложение** и открытие без сервера (PWA).

## Как пользоваться

1. **Добавить прибор:** «Добавить оборудование» → заполнить название, тип, серийный номер → «Сохранить».
2. **Выдать:** в строке прибора нажать «Выдать» → указать, кому, и дату → «Выдать». Статус сменится на «В использовании (ФИО)».
3. **Вернуть:** нажать «Вернуть» в строке прибора или на вкладке «Активные выдачи».
4. **Найти:** выбрать тип и/или статус в фильтрах над таблицей.
5. **Изменить или удалить:** кнопки «Изменить» и «Удалить» в строке прибора.

## Запуск

Нужен установленный [Node.js](https://nodejs.org/) версии 22.5 или новее (в нём есть встроенный модуль SQLite).

```
cd Lab8
npm install
npm start
```

Открыть: http://localhost:3002

Остановить: **Ctrl + C** в терминале.

Работает на порту 3002, поэтому можно запускать одновременно с ЛР №6 (порт 3000) и ЛР №7 (порт 3001).

База `equipment.db` создаётся автоматически при первом запуске. В неё сразу добавляются 4 прибора для примера.

## Схема БД (ER-диаграмма)

```
┌──────────────────────────┐          ┌──────────────────────────┐
│        equipment         │          │          loans           │
├──────────────────────────┤          ├──────────────────────────┤
│ id            PK INTEGER │ 1      N │ id           PK INTEGER  │
│ name          TEXT       │──────────│ equipment_id FK INTEGER  │
│ type          TEXT       │          │ borrower     TEXT        │
│ serial_number TEXT UNIQUE│          │ issue_date   TEXT        │
│ status        TEXT       │          │ return_date  TEXT / NULL │
└──────────────────────────┘          └──────────────────────────┘
```

- Одно оборудование может иметь много выдач (история).
- `status`: `available` (свободно) или `in_use` (в использовании).
- `return_date = NULL` означает, что выдача активна (оборудование ещё не вернули).
- Уникальный индекс `one_active_loan` не даёт создать две активные выдачи одного оборудования.
- При удалении оборудования его выдачи удаляются (`ON DELETE CASCADE`).

## API

| Метод | Адрес | Описание |
|---|---|---|
| GET | `/api/equipment` | список оборудования; фильтры `?type=...&status=available\|in_use` |
| GET | `/api/equipment/types` | список типов |
| GET | `/api/equipment/:id` | одно оборудование |
| POST | `/api/equipment` | добавить `{ name, type, serial_number }` |
| PUT | `/api/equipment/:id` | изменить `{ name, type, serial_number }` |
| DELETE | `/api/equipment/:id` | удалить (выданное удалить нельзя) |
| GET | `/api/loans` | активные выдачи |
| POST | `/api/loans` | выдать `{ equipment_id, borrower, issue_date }` |
| POST | `/api/loans/:id/return` | вернуть |

Ошибки (ответ `{ "error": "текст" }`):
- `400` — не заполнены поля, неверная дата или статус
- `404` — оборудование или выдача не найдены
- `409` — оборудование уже выдано / уже возвращено / повтор серийного номера / удаление выданного
- `500` — внутренняя ошибка сервера

## Примеры запросов (PowerShell)

```powershell
# Список оборудования
Invoke-RestMethod http://localhost:3002/api/equipment

# Фильтр по типу и статусу
Invoke-RestMethod "http://localhost:3002/api/equipment?type=Компьютер&status=available"

# Добавить
Invoke-RestMethod http://localhost:3002/api/equipment -Method POST -ContentType 'application/json' `
  -Body '{"name":"Генератор сигналов","type":"Измерительное","serial_number":"GEN-003"}'

# Изменить
Invoke-RestMethod http://localhost:3002/api/equipment/1 -Method PUT -ContentType 'application/json' `
  -Body '{"name":"Осциллограф","type":"Измерительное","serial_number":"OSC-001"}'

# Выдать
Invoke-RestMethod http://localhost:3002/api/loans -Method POST -ContentType 'application/json' `
  -Body '{"equipment_id":1,"borrower":"Иванов И.И.","issue_date":"2026-11-17"}'

# Повторная выдача того же оборудования → 409 «Оборудование уже выдано»

# Активные выдачи
Invoke-RestMethod http://localhost:3002/api/loans

# Вернуть (1 — id выдачи)
Invoke-RestMethod http://localhost:3002/api/loans/1/return -Method POST

# Удалить
Invoke-RestMethod http://localhost:3002/api/equipment/1 -Method DELETE
```

## Технологии

HTML5, CSS3 (Flexbox, mobile-first), JavaScript (ES6+, fetch, async/await), Node.js, Express, SQLite (`node:sqlite`), PWA.

## Структура проекта

- `server.js` — сервер, маршруты, проверка данных, обработка ошибок
- `db.js` — таблицы и все SQL-запросы
- `public/index.html` — страница: табы, таблицы, модальные окна
- `public/app.js` — логика страницы (запросы к API, отрисовка таблиц)
- `public/style.css` — стили (mobile-first)
- `public/script.js`, `public/sw.js`, `public/manifest.json`, `public/icons/` — PWA (из ЛР №6)
- `public/about.html` — о себе

## Ревью кода

- **Читаемость:** SQL-запросы собраны в `db.js`, маршруты в `server.js`, интерфейс в `app.js`. Сложные запросы (JOIN, транзакции) прокомментированы. Статусы — константы, а не строки по всему коду.
- **Без дублирования:** один helper `api()` для всех запросов и обработки ошибок, общие функции `cell()` и `actionButton()` для таблиц, общая функция `inTransaction()` для выдачи и возврата.
- **Валидация:** на клиенте (`required` и проверка в JS) и на сервере (ответ 400 с понятным текстом).
- **Семантика:** `header`, `nav`, `main`, `section`, `table` / `thead` / `tbody` / `th scope`, `dialog`, `label` у каждого поля.
- **Доступность:** `role="tablist"` / `tab` / `tabpanel` и `aria-selected` у табов, `aria-label` у кнопок в таблице, `aria-live` и `role="alert"` для сообщений, видимый фокус, модальные окна закрываются по Esc.
- **Безопасность:** данные выводятся через `textContent` (без `innerHTML`) — защита от XSS; SQL-запросы с параметрами `?` — защита от SQL-инъекций.
- **Производительность:** таблица перерисовывается одним проходом, статика кешируется service worker.
